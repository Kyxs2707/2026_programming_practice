# Agent 文档构建原则

> 说明：为满足禁用要求，本文用“禁用词表”指代任务中指定的七项词，不在原则文本中复述词项。Agent 产出任何文档时，禁用词表必须零命中。

## 1. 总则

- 文档只服务一个目标：让目标读者完成判断或行动。
- 每篇文档先写目的，再写适用对象、步骤或规则、示例、验收标准。
- 如果某句话的作用只是防止被质疑，而不是推进论证，请删除。
- 只写必要信息。删除后不改变读者行动、判断条件、责任边界或验收结果的句子，一律删除。
- 使用具体业务名词、动作、条件、结果；使用短句和主动语态。
- 一条规则一个句子；规则必须可执行、可验证。

## 2. 禁用词规则

- 禁用词表为 [forbidden_terms.yaml](../forbidden_terms.yaml)。
- 禁用词不得出现在标题、正文、表格、代码块、注释、图注、链接文字、文件名、元数据。
- 禁用词不得作为示例、反例、引用、免责声明或“禁止使用”清单出现。
- 需要表达相关概念时，用具体业务对象、动作、条件、结果改写；无法改写则删除该信息。
- 不得通过拆分、缩写、谐音、外文、符号拼接等方式保留禁用词表词项。
- 引用外部材料时，采用转述或省略；不得原样保留禁用词。
- 生成后执行全文检查；命中即改写或删除，交付前确认零命中。

## 3. 防御性废话规则

- 防御性废话指删除后不改变读者行动、判断条件、责任边界或验收结果的句子。
- 禁止无关否定转折。反例：“本文档说明安装步骤，但不涉及市场推广。”正例：“本文档说明安装步骤。”
- 禁止免责声明、假设反驳、重复强调、空泛警告、与主题无关的边界说明。
- 否定只用于真实边界。边界必须与当前规则同一主题，并说明处理方式或替代路径。删除后会影响执行判断才保留。
- 出现“是A，但不能B”式句子时，拆成两句；删除与主题无关的B；B必要时改为“当B发生时，执行C”的条件句。
- 不得用“注意、务必、请勿、以免、否则”包装无关内容。

## 4. 自检清单

- 禁用词表全文零命中。
- 每段只有一个主题。
- 每条规则可执行、可验证。
- 每个否定句与主题直接相关且必要。
- 删除后不改变行动或判断的句子已删除。
- 示例不引入新规则。
- 标题、正文、验收标准一致。
- 无免责声明、无假设反驳、无重复强调、无空泛警告。
- 交付前记录“检查通过”。

## 5. 违规处理

- 命中禁用词：改写为业务表达；无法改写则删除；不保留原词。
- 出现防止被质疑的防御性废话：删除整句；承载真实边界时改写为正面规则或具体条件。
- 出现无关否定：删除否定部分，保留主句。
- 出现无关转折：删除无关分句；必要边界改为条件句。

## 6. 正例

“本文档说明安装步骤。读者按编号执行。完成标准为服务启动且健康检查返回成功。”

反例：“本文档说明安装步骤，但不涉及市场推广。”

正例：“本文档说明安装步骤。”

## 7.文档目录分类与放置规则

文档按职责分类存放。新增文档按本节规则归入对应目录；专用目录与配置文件按本节第5项执行。

### 1. 目录职责与权限

- **`docs/rules/`（规则与原则）**
  - 存放内容：文档构建原则、协作规范、合并规则。
  - 编写权限：Agent 提供变更建议，由人工写入。
- **`docs/requirements/`（原始需求）**
  - 存放内容：业务需求、产品原始诉求。
  - 编写权限：人工编写与维护。Agent 只读。
- **`docs/specs/`（规范与设计）**
  - 存放内容：语言规范、架构设计、模块设计定稿。
  - 编写权限：人工主导，Agent 可辅助起草与完善。
- **`docs/specs/discussions/`（讨论记录）**
  - 存放内容：设计讨论过程、决策论证记录。
  - 编写权限：人工与 Agent 均可编写。
- **`docs/plans/`（实施计划）**
  - 存放内容：开发计划、任务拆解、里程碑。
  - 编写权限：人工与 Agent 均可编写。
- **`docs/reports/`（测试报告）**
  - 存放内容：测试结果、性能数据、缺陷统计。
  - 编写权限：Agent 自动生成，人工审阅。
- **`docs/guides/`（开发指南）**
  - 存放内容：构建步骤、测试命令、环境配置说明。
  - 编写权限：人工与 Agent 均可编写。

### 2. 放置判定流程

编写或新增文档时，按以下顺序判定归属：

1. 属于不可更改的业务诉求，放入 `requirements/`。
2. 属于约束团队的规则与原则，放入 `rules/`。
3. 属于技术定稿方案，放入 `specs/`。
4. 属于方案形成前的讨论过程，放入 `specs/discussions/`。
5. 属于任务分工与排期，放入 `plans/`。
6. 属于执行结果与数据，放入 `reports/`。
7. 属于操作说明与步骤，放入 `guides/`。

无法归入以上目录的文档，由人工决定存放路径，并更新本节规则。

### 3. 命名规则

- 文件名使用业务名词加文档类型。示例：`MYB语言规范.md`。
- 同一主题的多个版本，在文件名末尾加版本号。示例：`测试报告_v0.1.md`。

### 4. 只读目录约束

- `docs/rules/` 与 `docs/requirements/` 为只读目录。
- Agent 不得在这两个目录内新建、修改、删除或重命名文件。
- Agent 需要变更这两个目录的内容时，输出变更建议，交由人工处理。

### 5. 专用目录与配置文件

- `docs/superpowers`：存放 Superpowers 流程使用的文档，由人工与 Agent 维护。常规实施计划存放于 `docs/plans/`，相关计划通过链接关联。
- `docs/ci/`：存放 CI 配置核验和验收结果的结构化证据，由 Agent 按实际执行结果生成，人工审阅。已有证据保留当次事实，后续验收结果另行记录。
- `docs/forbidden_terms.yaml`：存放文档用词检查配置，允许保留在 `docs/` 根目录。由人工维护，Agent 提供变更建议。词项定义不参与自身词表检查，其他文档按词表执行检查。
