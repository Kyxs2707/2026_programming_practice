### 方法分工与限制

| 方法 | 采用范围与判定 |
|---|---|
| 分层测试 | C++ 内部断言检查不可从 MYB 观察的所有权、帧、根、栈效应；MYB 黑盒检查语言和进程契约；CLI 自测与驱动自测证明入口和测试工具本身。三层各自计数 |
| 表驱动与 golden | 按值类别、操作符、边界、阶段、出口组合列输入与独立预期。正常输出/文件逐字节比较；诊断采用原始字节或严格 UTF-8 后完整 regex。新增预期由规范推导并人工审阅 |
| 语法感知生成 | 计划补充；从 EBNF 生成已实现子集，正例同时保证结构合法、执行有界。负例一次破坏一条规则并标明预期阶段。原始字节变异单独负责坏 UTF-8、截断和词法边界 |
| 属性/蜕变 | 计划补充；每条性质声明前提。用精确宿主整数计算除余关系，比较关系须遵守 MYB 类型规则；GC 安排变化不改变正常结果；深拷贝保留图关系。浮点结合律、带副作用的交换和可能溢出的重排不作为等价性质 |
| 差分 | 计划补充；Debug/Release 各自通过同一独立预期，再比较成功输出和文件字节。错误路径各自验证绝对路径、位置和类别，不靠删路径或改换行获得一致。两配置共享缺陷时仍靠定向预期检出 |
| 受限参考计算 | Python 仅计算已明确的共同子集，如数学整数除余及显式 Int64 范围判断。Python 的任意精度整数、Bool 数值行为、真假转换、对象相等和浮点排版都不能自动成为 MYB 标准；不做整语言直接对比 |
| 故障注入 | 现有内部接缝检查资源失败和清理；任务 13–17 补遍历、工作区及 OS 失败。注入前确认实际路径命中，注入后检查首错、结果、计数与清理，不以退出非零一项代替全部判定 |

### 属性与生成的验收条目

以下是补充计划；已有数值随机回读继续作为现有覆盖登记。

- 除数非零、商可由 Int64 表示时，整数除余满足 `a = q*b+r`、`abs(r) < abs(b)`，且 r 非零时与 b 同号；参考计算使用数学整数，避免参考代码自身乘法溢出。MIN//-1 单独判为溢出，MIN%-1 单独判为 0。
- 有限 Float64 的格式化结果回读后位模式相同，包含负零符号；最短、最近、取偶与定点/科学记法仍用独立给定文本判定，不能由回读成功推出。
- 相同无故障程序在常规 GC 与逐允许点 GC 下，退出值、输出和文件结果相同；类型/范围等错误仍按原阶段判定。资源注入用例另按注入位置预期比较。
- 对象复制的原/副本可变身份不同，原图的重复边在副本仍指向同一对象，循环回到对应副本；修改副本后原图值不变。此项随任务 14 执行。
- 无活动遍历、位置合法且中间无其他修改时，先按插入前长度换算实际非负下标，insert 后用该下标 remove_at，应返回相同元素并恢复原长度与元素关系；比较元素值或身份，不以 Array 的身份相等代替内容检查。此项随任务 12–13 执行。
- 生成正例分别记录产生式、绑定状态、运算类型和退出路径分类；每个选定分类都须有实际样本。负例记录被破坏的单条规则及预期的前端/结构/运行/资源阶段，不能把任意非零退出都算成功。

### 故障与 GC 接缝的真实能力

`tests/internal/test_hooks.hpp/.cpp` 提供 `TestHooks::force_gc(bool)`、`fail_next(point)`、`clear_fault()`、`heap_counts(heap)`。`fail_next` 在下一次匹配 `hit` 时仅抛一次 `std::bad_alloc` 并清除设置；强制 GC 开关为进程共享，测试结束必须恢复。

- 已接入产品源的 10 类位置：HeapObject、HeapRegistry、Payload、MarkWorklist、ProgramConstants、VmValues、VmStates、VmFrames、FlexAllocation，以及诊断记录分配位置。
- NativeWorkspace、IterationRecords、OsRead、OsWrite、OsClose 目前只有枚举声明；`active_iteration_count(const VM&)` 也仅声明。它们须在相应任务中接入并证明命中，才能计为测试能力。
- `HeapCounts` 已有 live、marked、collecting、active_arrays。需要根或句柄的额外统计时，先在所属任务设计内部观测方式，不写成现有字段。
- 资源分配失败与 OS I/O 错误分开：单次 `bad_alloc` 不能模拟部分写入、零进度、broken pipe 或关闭失败。任务 16 的内部适配测试需提供实际 OS 结果控制并保持公开 HostIO 契约。
- 测试钩子仅在 `MYB_BUILD_INTERNAL_TESTS=ON` 编入；不得新增 MYB 内置、公开 CLI 开关或通过保留槽内残值保活对象。

## 五、精确 GC 与故障验证程序的安排

每个资源用例按“建立受保护输入 → 命中受控入口 → 检查首错和仍可达对象 → 明确撤根/清理 → 收集 → 检查计数”组织。收集前后比较可达图关系、live、marked、collecting 与已实现的活动数组统计；正常返回和异常退出都覆盖。

1. 已有根种类逐项隔离：全局、已初始化局部、有效操作数、编译期临时、全部函数单元常量、RootedValue、NativeRootSet。创建仅靠被测根可达的对象，避免常量表或额外根掩盖漏扫。
2. 任务 12–14 补参数、结果、构造半成品、被移出元素、复制映射/工作项、显示路径及 TextBuilder 增长。用真实副作用或对象身份判断共享和结果，不只检查程序是否存活。
3. 标记工作表失败必须证明未清除任何未完成标记的对象；恢复标记位和 collecting 后可整体销毁。失败时不重试分配，不继续执行 MYB。
4. 任务 13 的正常结束、break、continue、return、运行错误、记录登记失败分别检查解除责任；同一数组多次登记各自解除。保留数组的外部根，排除“对象已销毁所以计数不可见”的假结果。
5. 现有 fail_next 只支持“下一次”，多入口路径用独立测试控制到目标点；需要覆盖同一入口第几次失败时，在对应任务中设计可核验的内部扩充，不假定已有倒计数接口。每例结束清除故障并恢复 GC 开关。
6. 诊断低资源组合按任务 17 验收：先固定真实首错，再使详细报告失败；断言退出值、最多一次最小报告和清理完成。无首错的 bad_alloc 为 3；已有 MYB 错误时保留 1。

## 六、本地、PR 与失败工作流

### 现在可执行的入口

前提是 Windows、PowerShell 7+、UCRT64 GCC/Python、usr 下 Flex/Bison 与 Windows 原生 CMake/Ninja 已可发现。使用 `build/hosttools` 时先按[构建文档](../guides/构建与测试.md)设置 PATH；以下从仓库根执行。CI 脚本会重建本配置目录，该目录只存放可重新生成的文件。

本地针对性循环（已有对应 Debug 构建时）：

```powershell
& ./build/debug/myb_internal_tests.exe --case bytecode_verify
python -m unittest discover -s tests/driver -v
$env:MYB_INTERPRETER = (Resolve-Path ./build/debug/myb.exe).Path
python -m unittest discover -s tests/cli -v
python tools/run_blackbox.py --interpreter build/debug/myb.exe --manifest tests/blackbox/calls/manifest.json
```

正式本地检查分别运行下列命令，并立即核对各自退出值；第一条失败时先处理失败，不以第二条成功覆盖它：

```powershell
pwsh -File ./tools/ci.ps1 -Configuration Debug -Msys2Root D:/msys64
pwsh -File ./tools/ci.ps1 -Configuration Release -Msys2Root D:/msys64
```

一条命令运行当前默认 MYB 黑盒：

```powershell
python tools/run_blackbox.py --interpreter build/debug/myb.exe
```

通过标准为适用集合实际执行且全部通过，驱动/内部程序退出 0；当前计数按第一节核对。仅注册数和报告旧数字不能证明本次成功，新增用例后以实际 discover 和 manifest 为准。

### PR 检查与超时

- 现有 `windows-debug` 运行内部、driver、CLI 和默认黑盒；`windows-release` 关闭内部测试，检查无测试依赖，再运行 CLI 和默认黑盒。对 dev/main 的 PR、dev push、手工触发均保留；纯文档 PR 同样运行。
- 两项必须针对最新提交实际完成。检查名、来源和目标分支最新要求沿用 CI-02；规则是否满足读取当次 PR，不把旧运行或 skipped/neutral 当作测试已执行的证据。已有 CodeQL 三类分析另检查其结果及仓库要求。
- 黑盒默认单例 5 秒，现有 4096 层递归例显式 20 秒；超时即驱动失败 1，继续后续例，不虚构 MYB 退出码。CLI 子进程限时 5 秒；每个构建回归 job 限时 30 分钟，CodeQL job 当前 45 分钟。
- 本地 CI 脚本和内部测试当前没有单项超时。内部用例挂起会阻断该进程；本地由执行者中断并记为未通过，远端最终受 job 上限约束。任务 18 可补外部单用例隔离/限时编排，具体预算须经测量记录，不给 MYB 增加执行时限。
- 当前没有自动重试。修复前保留首次失败的原始输出、日志、配置与提交；重跑记录单独关联。失败 job 仍尝试上传已有日志，附件上传成功不抵消测试失败。

### 预期、语料与防止未执行却通过

1. 正式预期保存在 `tests/blackbox/` 各组并由默认 manifest 显式汇总。当前默认与分组 ID、输入关联和预期一致；计划在任务 18 增加持续一致性比较，保证新增分组不会被默认入口遗漏。每次汇总先核对 ID 唯一与规范化字段一致，不仅核对总数。
2. golden 由规范独立推导。变更同时提供规则依据、实际差异和审阅记录；驱动不自动改预期，不统一换行、不宽松替换坏编码。源码和输入作为原始字节保存，遵守 `.gitattributes`。
3. 正式驱动对空 cases 返回 2，重复 ID/未知字段/坏 regex/非正或非有限超时等配置错误为 2；用例失败、无法启动或超时为 1。stdout、stderr 精确文件和副作用文件均按字节，regex 用严格 UTF-8 与完整匹配，`$SCRIPT` 对实际 Windows 路径转义。
4. 当前 66 例 regex 中许多行列仅为 `\d+`，无法检出错误位置。计划按任务 07/11/12/17 对关键调用、赋值、索引和编码错误补独立给定的精确行列；消息非契约部分仍可限制在必要原因模式。
5. unittest 直接 discover 的空集合可能返回 0；正式 CI 包装器核对同一次发现得到的集合非空再实际执行。内部 `--case` 无匹配为 2。项目没有 CTest 注册，空 `ctest` 的成功不能替代现有入口。
6. 复核工具改动时保留正例→错误 golden/死循环→恢复的验证过程；错误必须使相应命令非零且下一例继续执行。测试工具的失败不能只由被测解释器自己的输出说明。
7. 拟新增生成测试按种子、已尝试数、成功生成数、拒绝/超时数及规则分类命中数报告。正例不能因未知语法或内部 3 退出而算通过；错误样本必须按既定阶段和类别判定。采样预算与必测边界随实现登记，任何选定分类未命中均明确列缺口。
8. 反例保存实际源字节、stdin、初始工作目录内容、预期、实际退出/输出、解释器提交、工具版本、构建、种子及超时。缩小后人工核验其仍触发同类缺陷，再转入正式 MYB 用例；只保存种子不足以长期重放。
