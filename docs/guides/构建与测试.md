# MYB 构建与测试

更新：2026-10-26。当前交付 M3（实施计划任务 01–16），真实控制台验收状态见 [Windows 终端验收](../reports/Windows终端验收.md)。

## 当前支持范围

- 执行 UTF-8 源文件；中文及含空格路径，无文件后缀要求；支持开头 BOM、LF/CRLF/CR 源码换行。
- Int64、有限 Float64、Bool、Null、不可变 String 字面量；科学计数法、规范规定的字符串转义和 `#` 注释。
- 表达式语句、括号、一元 `+ - !`、数值 `+ - * / // %`、字符串拼接、精确混合数值比较和字符串码点排序；动态检查类型、除零和溢出。
- `let` 声明、初始化与赋值，三态绑定、块作用域和遮蔽；严格 Bool 的 `&&`、`||`、if/else、while、for、break/continue。
- 顶层函数、固定位置参数、显式返回或默认 null 返回、前向互递归；VM 使用独立参数槽和显式帧，不借宿主递归执行用户调用。
- 固定一个位置参数的 `print(value)`、`write(value)`；目标和参数数量在求实参之前检查，返回 null。
- `myb <file>`、`--check <file>`、`--help`、`--version` 和 `--` 选项终止符；退出状态 0/1/2/3。
- 源码经完整语法解析、全文件结构检查、全部单元生成与核验后才执行。`--check` 不执行 MYB、不调用内置、不消费程序 stdin；名称存在性、初始化、动态类型、调用数量与构造字段集合保持运行时检查。

数组与命名结构支持构造、访问及修改，索引与切片遵守原接收对象和求值顺序；for 按数组元素或字符串码点遍历，活动遍历期间禁止增删同一数组。deep_copy 保留副本内部的共享与循环，print/write/str 共用确定显示规则。

全部 21 个内置均可执行：数组操作、数值转换、断言、文本处理、行输入和整文件读写。静态描述表固定名称与参数数量，声明保护与调用预检共用该表。Windows 文件和管道使用 UTF-8 字节，控制台使用宽字符桥接；真实控制台组合待人工实测。

`examples/functions.myb` 使用函数、局部变量和循环，输出最大公约数 `6` 与奇数之和 `25`。运行错误包含实际源码位置和已进入的用户函数链；实参求值或子帧准备失败时，尚未进入的目标不出现在链中。

## 工具与目录

共享 CMake 不硬编码本机路径，不联网下载依赖。需要 Windows 原生 CMake 3.24+、Ninja 1.11+、Python 3.10+，以及已确认的 UCRT64 GCC、Flex、Bison。编译器仍是 C++20，Ryu 单独按 C99 编译。

| 本次验证工具 | 版本/位置 |
|---|---|
| GCC | 15.2.0，`D:/msys64/ucrt64/bin/g++.exe` |
| Flex / Bison | 2.6.4 / 3.8.2，`D:/msys64/usr/bin/` |
| CMake / Ninja | 4.1.0 / 1.13.0，局部安装到 `build/hosttools` |
| Python | UCRT64 3.12.12 用于验收；CMake 初次发现 Anaconda 3.13.5 |

本次使用用户已安装的 Bison。CMake/Ninja 安装在被忽略的构建目录中。如果已有原生安装，可直接使用其命令并省略下面的局部安装。

```powershell
# 在仓库根目录，使用一个带 pip 的 Python；不修改机器全局安装。
python -m pip install --disable-pip-version-check --no-deps --target build/hosttools cmake==4.1.0 ninja==1.13.0
$mybCMake = (Resolve-Path build/hosttools/cmake/data/bin/cmake.exe).Path
$mybNinja = (Resolve-Path build/hosttools/bin/ninja.exe).Path
$env:PATH = 'D:/msys64/ucrt64/bin;' + $env:PATH
```

`src/frontend/lexer.l`、`parser.y` 和手写 C++ 是维护入口；生成头和源码位于各配置的 `build/.../generated`。不要修改或提交生成物。Debug 和 Release 使用独立目录。

## Debug 构建与运行

```powershell
& $mybCMake -S . -B build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=D:/msys64/ucrt64/bin/g++.exe -DCMAKE_C_COMPILER=D:/msys64/ucrt64/bin/gcc.exe "-DCMAKE_MAKE_PROGRAM=$mybNinja" -DFLEX_EXECUTABLE=D:/msys64/usr/bin/flex.exe -DBISON_EXECUTABLE=D:/msys64/usr/bin/bison.exe -DMYB_BUILD_INTERNAL_TESTS=ON
& $mybCMake --build build/debug --parallel 4
& .\build\debug\myb.exe .\examples\hello.myb
& .\build\debug\myb.exe --check .\examples\hello.myb
```

第一个运行命令输出 `3` 加 LF；检查成功没有输出。源文件仍直接交给解释器，MYB 用户不需要单独编译或链接。只有解释器开发者构建宿主程序。

## 测试

```powershell
& .\build\debug\myb_internal_tests.exe
python -m unittest discover -s tests/driver -v
python -m unittest discover -s tests/cli -v
python tools/run_blackbox.py --interpreter build/debug/myb.exe
```

内部程序支持 `--case checker_contract`、`--case bytecode_verify`、`--case value_ops`、`--case vm_calls`、`--case vm_call_failure_states` 等单项入口。内部断言在 Release 中也不消失；故障接缝仅在 `MYB_BUILD_INTERNAL_TESTS=ON` 时编入，不暴露为 MYB 内置、CLI 选项或环境开关。

黑盒 manifest 默认入口为 `tests/blackbox/manifest.json`；当前聚合 235 个用例（原有 110、对象 46、遍历 22、显示 4、内置 29、I/O 24）。每例使用独立进程与临时工作目录，逐字节核对输出，默认 5 秒超时。失败继续统计，驱动退出 0=全部通过、1=用例失败/超时、2=驱动参数或 manifest 错误。不要自动重写预期或归一化换行。数值、源码编码和 NUL 测试数据的原始字节由 `.gitattributes` 保留。

## Release 构建与验收

```powershell
& $mybCMake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=D:/msys64/ucrt64/bin/g++.exe -DCMAKE_C_COMPILER=D:/msys64/ucrt64/bin/gcc.exe "-DCMAKE_MAKE_PROGRAM=$mybNinja" -DFLEX_EXECUTABLE=D:/msys64/usr/bin/flex.exe -DBISON_EXECUTABLE=D:/msys64/usr/bin/bison.exe -DMYB_BUILD_INTERNAL_TESTS=OFF
& $mybCMake --build build/release --parallel 4
python tools/run_blackbox.py --interpreter build/release/myb.exe
$env:MYB_INTERPRETER = (Resolve-Path build/release/myb.exe).Path
python -m unittest discover -s tests/cli -v
```

Release 禁用 fast-math 和浮点收缩，测试钩子关闭。CLI 外部测试默认使用 Debug，可用 `MYB_INTERPRETER` 选择另一个构建；这是测试驱动的配置，不是 MYB 语言接口。

## CI 同等入口

```powershell
pwsh -File ./tools/ci.ps1 -Configuration Debug -Msys2Root D:/msys64
pwsh -File ./tools/ci.ps1 -Configuration Release -Msys2Root D:/msys64
```

CI 脚本要求 PowerShell 7+（GitHub runner 已预装），Windows PowerShell 5.1 会在执行前明确拒绝。脚本从自身位置确定仓库根，不依赖调用者的工作目录。MSYS2 安装根为参数；gcc/g++/Python 来自 UCRT64，Flex/Bison 来自 usr/bin，原生 CMake/Ninja 优先从 UCRT64 查找，也允许通过 PATH 提供。沿用上述局部工具安装时，先将 `build/hosttools/cmake/data/bin` 和 `build/hosttools/bin` 加到 PATH。同一 UCRT64 Python 显式传给 CMake，并用于全部 Python 测试。

每次运行会清理所选配置的 `build/debug` 或 `build/release` 后重新并行构建。这两个目录只存放可重新生成的构建文件。Debug 执行全部内部测试、动态发现的 driver/CLI unittest 和默认黑盒；Release 关闭内部测试，核对编译命令不含测试钩子/测试目录依赖，再运行 CLI unittest 和默认黑盒。空 unittest suite、空黑盒清单、工具缺失、超时及任何命令失败均返回非零，不继续执行后续步骤。

日志位于 `build/ci-logs/debug/ci.log` 和 `build/ci-logs/release/ci.log`，包含提交 SHA、实际工具版本、configure/build/测试输出。GitHub Actions 的两个固定 job 为 `windows-debug`、`windows-release`，即使失败也尝试上传已有日志。远端运行与强制合并条件的验收记录见 [CI 与合并规则](../rules/CI与合并规则.md)。

## 固定依赖与已知限制

`third_party/manifest.json` 保存 fast_float v8.3.2 和 Ryu 59661c3 的完整提交号、上游不可变归档 URL、归档与逐文件 SHA-256、原许可。configure 离线核对每个导入文件；不依赖运行时下载。

Flex 2.6.4 的 `yy_scan_buffer` 虽然接收 size_t，内部仍保存为 int；超过 INT_MAX 字节的源码在复制前以 Resource/Capacity（退出 3）拒绝，避免窄化。

本机 CMake 4.1.0 对同时含中文和空格的构建输出目录曾异常退出。普通 `build/debug`、`build/release` 已通过；中文/空格 MYB 源路径已通过。该工具路径问题、完整干净/增量构建矩阵与真实控制台组合留到 M4/M3 验证，不将管道测试冒充控制台验收。

在 Codex 受限沙箱中，MSYS 启动及 Python 临时目录可能需要受控审批。遇到权限错误先区分环境失败与用例语义失败，不将无法启动测试登记为语言测试的失败或通过。

当前验收、故障覆盖与实施调整见 [M3 测试报告](../reports/M3测试报告.md)，M2 历史结果见 [M2 测试报告](../reports/M2测试报告.md)。
