## 三项修复与行为约束

| 缺陷 | 原因与修改 | 保留的语言行为 |
|---|---|---|
| B01 调用及 Schema 反复查表 | VM 每次调用扫描用户函数，构造目标也逐次扫描 Schema。[ExecutionIndex](../../src/vm/execution_index.cpp)在首帧发布前使用实际 Registry 与 Program 准备只读目标表，调用按编号取得结果 | PRECALL 仍在实参之前检查目标和数量；未知目标只在实际执行路径失败，空回调仍在实参求完后由 CALL 报错 |
| B02 结构字段重复平方匹配 | 构造字段集合检查、字段槽查找和最终写入反复遍历声明字段。索引拥有字段表，并按单元及构造方案保存匹配状态和源码字段到声明槽的映射 | 无效构造状态在 CHECK_STRUCT 执行时报告；CHECK_FIELD 仍逐字段检查动态值和提升，失败后停止后续求值；BUILD_STRUCT 每次新建实例 |
| B03 入口诊断丢失绝对路径 | 入口已解析绝对路径，但错误分支追加原始参数。[read_entry](../../src/platform/windows_io.cpp)在打开文件前保存绝对路径的 UTF-8 文本，打开、读取及关闭错误复用该文本 | 解析或编码未完成时回退原参数；先保存 EntryIO 首错与 OS 代码，再分配错误消息；退出 2、无虚构行列或用户调用链 |

索引只拥有宿主辅助数据，不增加受管 Value 或 GC 根；借用的程序、Schema 和实际内置描述覆盖执行寿命。准备成功后一次交换发布，VM 清理时撤销索引；`--check` 完成编译核验后返回，不进入索引准备。

## 本地 CI 与性能检查

性能统一使用 `E = median(正常执行耗时) - median(--check耗时)`。B01 检查内置和后部用户函数的 `E(5000)/E(0) ≤ 1.5`；B02 检查 `E(1024)/E(256) ≤ 6`。用于比值的 E 至少 100 ms，正常执行波动按 `(最大值-最小值)/中位数` 计算，上限为 20%。输出、退出码和 stderr 先校验，测量不足返回非零。

每次 PR 的 Release 流程只向 [check_performance.py](../../tools/check_performance.py)提供当前 Release EXE，在当前程序的不同规模间比较 E。CI 不调用 `verify_fixes.py`，不需要旧 EXE，也不检查新旧耗时 25% 比例。两项分别记录结果，B01 失败后继续收集 B02；失败或测量不足使对应 CI 返回非零。旧版补充数据不足不影响 PR 性能判定；远端必需检查和合并拦截仍待实际验证。

`dc63553` 新增 Windows 测量进程控制：创建子进程前把测量父进程限定到允许 CPU 集合中的单一逻辑 CPU，子进程继承亲和性；创建时通过 `creationflags` 设置 `ABOVE_NORMAL_PRIORITY_CLASS`，随后逐个回读亲和性和优先级。退出时恢复父进程原亲和性；设置、子进程核对或恢复失败均记入错误并使测量失败。新控制的 [5 项自测](../../tests/driver/test_check_performance.py)先出现 [5 个预期失败](../../build/bugfix-20261028/python-driver-controls-red.log)，实现后 [39 项驱动自测全部通过](../../build/bugfix-20261028/python-driver-controls-green.log)。

最终记录中 `execution_controls.status` 为 `restored`：原掩码 65535，选定掩码 16384，恢复后仍为 65535。132 个子进程的实际掩码均为 16384，实际优先级均为 `0x8000`，全部匹配，`errors` 为空。该控制仅改变测量进程调度，原验收阈值保持不变。
