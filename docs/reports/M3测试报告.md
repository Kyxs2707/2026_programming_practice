图测试在允许分配点强制 GC，验证原图、副本、半成品及结果交接的保活。副本保持内部共享和循环，修改副本不改变原图。正常回收阈值下的 50000 层数组链完成复制、100002 字节显示和回收，未按图深递归宿主栈。

文本和 I/O 测试覆盖分配失败时保留旧输出根、片段清理、首个合法输入行之后的坏编码延后报错、跨 4096 字节块字符、真实匿名管道写失败、读写关闭错误码及启动工作目录。控制台的人工结果单独记录。

## 红绿过程与修正

对象、图、内置和 I/O 的新增测试先在 M2 程序或库上失败；遍历黑盒 22 项在接入指令前全部失败。实现后通过上述完整两配置验收。

独立审查发现连续追加会逐项精确扩容。改为 Heap 集中按几何增长申请容量，并保留元素、字节上限、GC 与实际容量记账检查。4096 次真实追加的容量变化从 4096 次降到 22 次；共享元素、全部内容与扩容失败保留原数组的检查通过。

断言消息含 NUL 时原有异常转交会截断消息，现通过完整字节视图传递。诊断按 Unicode 码点转义 C1、U+2028/U+2029。两项新增用例均先失败再通过。Debug 另用已写标记检查 native 输出交接，遗漏写入时报告内部错误。

首轮完整 CI 检出入口读取失败丢失文件名。恢复入口路径诊断，并在拼接消息前保存首错；原有 CLI 测试复验通过，随后重新运行的完整 Debug、Release 均退出 0。

对象、图和平台模块按文件分工实施，主代理统一登记内置、聚合清单并完成集成。改动位于从已同步 `main` 的本地 `dev` 创建的 `codex/myb-m3` 分支。

## 普通终端启动修正

用户在未配置 UCRT64 PATH 的 PowerShell 中运行 Release 时无输出。复现退出码为 `0xC0000135`：构建目录缺少 GCC 运行库，进程未进入解释器入口。

构建现从所选编译器目录复制 `libgcc_s_seh-1.dll`、`libstdc++-6.dll` 和 `libwinpthread-1.dll` 到 EXE 旁。两个可执行目标共用一次复制，增量构建可恢复缺失的运行库，不修改用户全局 PATH。

新增 `test_relocated_application_runs_without_development_path`：将程序及同目录 DLL 复制到独立 Unicode 路径，仅为子进程保留 Windows 系统目录 PATH，逐字节核对版本、中文脚本输出和文件读写。修正前因 `0xC0000135` 失败，修正后通过。

本次 Debug CI 退出 0：65 个内部测试、10 个驱动测试、8 个 CLI 测试及 235 个黑盒通过。Release CI 清理顶层目录时遇到外部进程占用；在已清空的同一目录重新配置构建后，8 个 CLI、235 个黑盒及 38 条编译命令隔离检查全部通过。日志位于 `build/example-checks/runtime-*.log`。

移走 Debug 的一个运行库后，增量构建未重新链接 EXE 即恢复该文件；普通 PATH 下 Release `--version` 退出 0。独立差异审查与差异格式检查通过。
