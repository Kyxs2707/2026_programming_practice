## 覆盖证据

- 前端：全部 29 个具体 AST 节点、完整文法、空程序/块/函数/结构、优先级与非链式比较、赋值目标、字符串转义、数字范围、源码位置和失败清理。Bison 启用两类冲突的错误选项，生成退出 0。
- 检查器：顶层名称冲突、21 个内置与类型名称保护、参数与函数外层体同层、for 来源与体绑定、字段类型前向引用、未执行路径和未调用函数的结构检查；未知名称、数量、自初始化与构造字段集合保持运行时检查。
- 字节码：声明点绑定、独立函数单元、参数与局部连续区间、全部操作码、绝对跳转回填、控制流汇合与死代码结构核验；产物不借用 AST，所有单元的常量由程序根保活。
- 动态运算：Int64 溢出、向下整除和同除数号余数、MIN 与 -1、正负零、有限浮点与下溢、2^53 和 Int64 两端的精确混合比较、严格 Bool、Unicode 字符串排序和拼接、对象身份。
- VM：全局与局部的未声明/未初始化区别、动态改绑、声明前查找、遮蔽和块退出、严格 Bool 短路、if/else、while、最内层 break/continue、右侧完整求值后赋值。
- 调用：固定数量预检、从左到右求实参、独立参数槽、词法全局、默认 null、前向互递归、4096 层递归、循环中返回、真实调用链与当前指令位置；失败目标不提前进入链。
- 根与故障：逐允许点强制 GC、返回对象和 native 结果交接、参数与结果槽重叠、零参数结果、编译常量和 VM 扩容失败、值区增长成功后状态区失败、诊断分配失败保留首错；错误清理后回收不留下对象。

默认黑盒由原有 25 个、前端 23 个、标量 32 个、调用 30 个用例组成，共 110 个；所有预期独立编写，逐字节核对输出。`examples/functions.myb` 实际输出 `6`、`25` 两行。

## 红绿过程与实施调整

前端、字节码与动态运算先运行新增测试，观测到 M1 缺失语法、接口或控制流核验能力；变量与函数测试链接旧 M1 库时 3 项失败，接通 M2 后转绿。工具或沙箱权限失败不计为语言行为的失败证据。

前端、编译器与运算模块按文件分工实施，主代理整合 VM、默认清单和文档。M2 的编译产物、值区与调用帧相互依赖，统一提交可构建的里程碑，提交信息按项目要求使用中文。

静态内置描述表扩为全部 21 个名称与固定数量；M2 的实际回调为 print/write，其余 19 个在 M3 接入。公开执行能力与完整语法检查分别验收。

本机使用仓库原有 CMake/Ninja 工具，并将其加入当前进程 PATH。Flex/Bison 在受限沙箱内需要受控运行；黑盒临时目录可置于 build 中。原始本地日志保存在 build/m2-work 和 build/ci-logs，均不提交。
