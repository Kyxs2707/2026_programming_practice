# MYB 项目实施步骤

> 给后续执行本计划的 Agent：按任务逐项推进并用复选框记录状态；执行时使用 `superpowers:executing-plans`，如用户选择子代理执行方式则使用 `superpowers:subagent-driven-development`。先完成语言和架构设计，再实现依赖这些设计的模块。

**目标：**完成 MYB 通用脚本语言、解释器、自动黑盒测试、Python 性能对比、开发指南以及 Agent 辅助开发的完整应用。

**架构：**C++20 实现解释器，源码经 Flex/Bison 构建 AST，再经检查、字节码生成与核验交给栈式 VM；用户直接运行源文件。Heap 统一管理不移动对象并进行标记—清除，VM 使用统一值区与显式调用帧。语言规范 v0.2 已于 2026-10-19 获整体批准，完整解释器设计已于 2026-10-22 获整体批准；语义和接口分别以 [语言规范](../../specs/MYB语言规范.md) 与 [解释器设计](../../specs/MYB解释器设计.md) 为准。

**技术栈：**C++20、MSYS2 UCRT64 GCC、Flex/Bison、CMake/Ninja、Python。AST 采用 C++ 节点继承与 unique_ptr 树形所有权。M1 已验证本机 Debug/Release 干净构建和 Windows GitHub Actions 构建；工具版本、路径、配置与复现命令见 [构建与测试](../../guides/构建与测试.md)。Python 用于外部测试驱动和性能测量，语言测试程序及应用使用 MYB。

**需求依据：**[原始需求文档](../../requirements/原始需求文档.md)。本文吸收了此前参考调研和后续 Flex/Bison 讨论，作为接下来的统一工作清单。创建日期：2026-10-11。

**设计讨论进度：**语言规则与修订历史见 [MYB 语言设计讨论记录](../../specs/discussions/MYB语言设计讨论记录.md)；宿主选择、工具链验证及解释器设计进度见 [MYB 解释器设计讨论记录](../../specs/discussions/MYB解释器设计讨论记录.md)。讨论中的旧方案保留为历史，当前语义与接口以已批准的规范、设计为准。

**实施进度（2026-10-26）：**M1 任务 01–06、CI-01/CI-02 已验收，M1 与 CodeQL 已通过 PR 合入 main，dev 已同步 main。M2 任务 07–11 已通过本地 Debug/Release 验收和独立审查，M3 任务 12–16 已完成运行时实现和自动化验收，真实控制台组合待人工实测；下一阶段为 M4。阶段证据与现行分支保护见第六节。

评分分配：解释器 20、自动测试 20、性能测试 10、说明与指南 20、Agent 应用 30。安排工作时应为测试、文档和应用保留足够精力。

全局约束：测试程序使用 MYB；外部驱动可以使用 Python；应用逻辑必须由 MYB 承担。原始需求没有要求 GUI、JIT、并发、继承或性能超过 Python，这些不作为首版交付的前置条件。

## 二、执行顺序与贯穿性工作

**主线：需求范围 → 语言设计 → 解释器设计 → 最小执行链 → CI 自动构建与合并检查 → 完整前端 → 基础字节码生成与运行时 → 控制流与函数 → 复合类型及 I/O → 测试收口 → 指南 → Agent 应用 → 性能报告 → 交付验收。**

从步骤 4 开始，每增加一项可观察功能，就先写对应 MYB 用例和预期，验证当前实现尚不满足，再实现并运行回归。步骤 9 用于查漏补缺，不是第一次开始测试。

每完成一个可验收的小任务，就更新规范或指南，记录测试结果，并提交相关文件。不要等项目结束后才补造 Git 历史或 Agent 开发过程。

重点审查的五类情况已经分配到后面的任务：

| 容易遗漏的情况 | 预期行为 | 所属步骤 |
|---|---|---|
| 中文字符串、CRLF 换行、路径含空格、输入 EOF | 编码和定位规则一致，命令行可用，EOF 行为可预测 | 4、5、8 |
| 最小负整数、溢出、负数除法、除零 | 按 MYB 规则求值或报错，避免 C++ 未定义行为 | 2、6 |
| 数组/记录共享、循环引用、连续创建对象 | 更新和生命周期符合规范，不悬空，不无界隐性泄漏 | 3、8 |
| 循环中 return、函数递归、异常后的环境恢复 | 控制流和调用栈正确，资源可释放 | 7 |
| 测试脚本死循环、输出错误、非零退出 | 驱动能超时终止、判失败并继续其他用例 | 4、9 |
